# Build plan (condensed)

Full narrative version lives with the director. Phases and exit criteria:

0. Repository and cloud environment — repo exists, GitHub App connected, environment created, seed files merged. (This scaffold session.)
1. Reconstruct — seed CSVs recovered from transcripts committed to `scenarios/legacy/seed/` (`data/seed/` until the 9c scenario split) with provenance in scenarios/legacy/RECONSTRUCTION.md; `tests/test_seed.py` guards the counts. Further reconstruction (holders, clocks, matrix, climate, events) lands as additional seed files in later sessions. Exit: seed tests green; director accepts the reconstruction record.
2. Reference data — done: `ridings.csv` (343, 2023 Representation Order) and land `adjacency.csv` (894 edges) built from the Elections Canada digital boundary file, retrieved via the GitHub mirror `opennorth/represent-canada-data` after direct access to Elections Canada / Government of Canada domains was blocked by this environment's network policy; `geometry_simplified.geojson` retained for the map exporter. Water-only adjacency remains a manually maintained register for a later session. Exit criterion "every tracker riding resolves to exactly one reference row" is not fully met: 142 of 143 `scenarios/legacy/seed/holdings.csv` ridings resolve; one (Ville-Marie—Le Sud-Ouest—Île-des-Sœurs, œ ligature) does not match the official spelling (Île-des-Soeurs) and is flagged, not silently reconciled.
3. Schema — done: `hoc/schema.sql` (ridings, adjacency, houses, holders, holdings with seat_order and partial uniqueness, successions, turns, events with `era_cohort`, event_houses, relations, climate per era-cohort, clocks, watch/threads/handoff, views `v_house_colours` and `v_current_climate`), `hoc/db.py` connection helper with foreign keys enforced, `scripts/load_seed.py` rebuilding `hoc.db` from the active scenario's seed + data/reference, and `hoc.db` committed. `tests/test_db.py` rebuilds into a temp path and guards the counts and invariants. Exit met: the seed loads with zero constraint violations (`PRAGMA foreign_key_check` clean).
4. Rules engine — done: `hoc/rules.py` with validate_expansion / expand / release_holding / transfer_holding, house_colours, succeed, set_clock / advance_clock / sync_clocks, climate_shift / current_climate / cohort_fit, elevate and record_event, all operating on an open connection and committing nothing (the turn runner owns the transaction). `tests/test_rules.py` covers them from logged cases. Rules that were not recovered are explicit parameters, listed in scenarios/legacy/RECONSTRUCTION.md "Rules not recovered". Exit met: suite green.
5. Turn runner — done: a turn is a JSON file (`turns/NNNN_<slug>.json`, format in docs/TURN_FILE.md) validated by `hoc/turnfile.py` and applied by `hoc/turn.py` in one transaction — turns row, event, operations in order, watch and threads — rolling the whole turn back and naming the failing operation index on any error. CLI in `hoc/__main__.py`: `apply`, `export`, `status`, `check`. The turn procedure is written up in CLAUDE.md. Exit met: `tests/test_turn.py` applies a turn, and proves a failing second operation leaves the database untouched.
6. Exporters — done: `hoc/export/dump.py` (a CSV per table plus state.json, deterministic ordering), `hoc/export/workbook.py` (outputs/Riding_Tracker.xlsx: Riding Tracker, Houses, Successions, Climate, Relations, Matrix, Events, Watch, Handoff — plain cells, frozen bold headers, hex cells filled with their own colour), `hoc/export/map.py` (outputs/map.svg and map_secondary.svg, Lambert Conformal Conic, legend by riding count). Exit criterion "diffs cleanly against baseline" cannot be met as written — the baseline workbook no longer exists (scenarios/legacy/RECONSTRUCTION.md); the workbook is instead checked structurally by the test suite and read by the director.

9. Autoplay engine — a game that plays itself, replacing the director-scripted turn loop with houses that hold stats and objectives, act from weighted tables, and respond to a deck of real events. Full design in docs/ENGINE_DESIGN.md.
   - 9a — done: docs/ENGINE_DESIGN.md, the director's design document (scenarios, time and era bands, house state, objectives, the season loop, the full action table with enclosure and late-game rules, the event deck shape, mortality and succession, founding, determinism/logging, console controls, site additions, build phases, the director's 6 September decisions, and the 9c smoke-test sanity targets).
   - 9b — done: the design's numeric tables transcribed to machine-readable files under `rules/` (actions, objectives, mortality, founding, succession, eras, responses) with a validating loader, `hoc/rules_data.py`, then the authored data banks (event deck to 1960, communities, surname and given-name banks, place banks) in 9b-2. Rules version 0.3 settles the seven questions the transcription left open — see `rules/CHANGELOG.md`. Exit met: `tests/test_rules_data.py` and `tests/test_banks.py` green.
   - 9c — done: the engine. `hoc/sim.py` holds the season loop, the seeded logging RNG, mortality and succession, founding, era events and responses, all seventeen §7 actions (Expand, Invest, Cultivate influence, Name heir, Endow, Petition elevation, Consolidate; Correspond, Propose compact, Reconcile, Dispute, Challenge, Purchase riding, Marriage alliance, Absorb, Cede/swap; and Partition, which is forced by a death rather than drawn), §7b enclosure with the Siege objective, and §7c's riding losses. `hoc/palette.py` assigns colours and `NameGenerator` in `hoc/names.py` draws names against `rules/denylist.csv`. `tests/test_sim.py` covers determinism, naming, mortality, founding, event scope, replay and the 300-season × 3-seed smoke run against §17. Rules versions 0.4 and 0.5 record the two design numbers the smoke test forced (founding coefficient 0.25→0.50, partition threshold 4→9 holdings) with the measurements behind them.
   - 9d — done: conflict, the site's season history, the Archive, and the switch to the live game. `rules/friction.json` (rules 0.6) gives grievance a source — per-pair friction across a shared land border, contested expansion, and a Correspond that can give offence — so disputes and challenges became a live part of the game instead of a rounding error. `stat_snapshots` and `house_actions` carry the history the tables never kept; `hoc/export/timeline.py` writes it to `outputs/site/data/timeline.json` as a per-season diff (118 KB at 300 seasons) for the index's season scrubber. House pages gained sparklines, objectives, action history, people and partition lines; the chronicle groups by season; the climate ledgers are drawn as inline SVG. `scripts/build_archive.py` renders the frozen legacy playthrough into `outputs/site/archive/` on every export. The live game began at season 1 under seed 1867.
   - 9e — done: the engine runs in GitHub Actions on demand from the site's console. `.github/workflows/engine.yml` takes `run`, `intervene`, `rules` and `rebuild` on workflow_dispatch, guarded to the director, serialised and never cancelled; `scripts/engine_command.py` carries the logic and writes a run summary either way; `scripts/apply_rules_patch.py` tunes numeric fields only. The engine gained all six stop conditions, a machine-readable run summary, and the §12 interventions (`set_objective`, `veto_objective`, `force_action`, `adjust_stat`, `grant_house`), replayed back into place by `scripts/rebuild.py`. `outputs/site/console.html` is the director's controls, holding no token of its own. Narration is a block of text for a Code session — no model is called by any workflow. Was: console — run-N-seasons, pause conditions, director intervention, a rules panel, and Claude-generated narrate blocks from the logged events.

10. Two engines — the game runs in the browser as well as in Python, and the two are held to playing the same game.
   - 10-1 — **done** (this phase): portable determinism and the JavaScript port's foundations. `hoc/prng.py` replaces `random.Random` with xoshiro128\*\* on unsigned 32-bit words, seeded by splitmix32 from `fnv1a32("seed:season")`, with `rand_int` by rejection sampling and `weighted_choice` by integer cumulative scan. Rules version 0.7 makes every weight and probability an integer; `hoc/palette.py` becomes integer HSL with an exact integer hex conversion; `p_found` is written as a square root, the only floating-point computation left. Season files are canonical JSON and name the engine that wrote them. `docs/DETERMINISM.md` states every algorithm with worked examples. `web/engine/` holds `prng.js`, `csv.js`, `palette.js`, `names.js`, `rules.js`, `adjacency.js` and `state.js` as plain ES modules with no build step and no dependencies, each verified value-for-value against its Python counterpart by `tests/test_js_engine_parity.py`. `scripts/crosscheck.py` and `tests/test_crosscheck.py` are the harness that will hold the season loops together. The live world was restarted at rules 0.7 on seed 1867. **Not done: `web/engine/sim.js`, `index.js` and `cli.js` — the season loop itself.** Until those exist the cross-check has nothing to compare and skips, saying so.
   - 10-2 — pending: the live UI. The browser plays seasons against `web/engine/`, with the map and the chronicle updating as it goes.
   - 10-3 — pending: commit from the browser. A game played in the page can be pushed back to the repository as season files, through the console's existing token.

Backlog: nine TBD secondary colours; full climate replay from 1867; per-house timeline SVG; routine to regenerate outputs on push; recover per-riding settler/generation/notes and Section 5 house blocks from transcripts.
